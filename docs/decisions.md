# Решения

Журнал решений, принятых по ходу разработки. Новое — сверху.

## 2026-10-26. Раунд с живой крупье (этап 4)

1. **Commit–reveal на сервере.** Игрок и крупье отправляют `sha256("{число}:{соль}")`, затем раскрывают.
   Числа соперника не видны до расчёта. Ставка со сбором списывается в банк в момент коммита.
2. **Таймауты** (серверное время, фоновый обработчик раз в секунду): не закоммитили оба за 10 с — отмена
   с полным возвратом (вместе со сбором); не раскрылся один за 10 с — проигрыш ему; никто — отмена.
3. **Результат подписывается Ed25519** (`ROUND_SIGNING_KEY`), публичный ключ — `GET /rounds/public-key`.
   Завершённый раунд в БД неизменяем (триггер) — это журнал раундов.
4. **Взаимность проверяет сервер**: открыта после 3 завершённых раундов пары игрок–крупье; ставка равна
   цене предмета; снятый предмет повторно не выбрать.
5. **Пока в эфире есть реальные крупье, демо-столы скрыты**, и баланс берётся из кошелька core.

## 2026-10-26. Комиссия, крупье, режим взаимности

1. **Комиссия площадки** (заменяет прежний rake 5% от банка):
   - **сбор 2,29% со ставки** каждого участника при любом исходе (`stakeFeeBps = 229`), удерживается
     при коммите ставки вместе с ней из депозита сессии;
   - **10% с выигрыша** победителя (`winFeeBps = 1000`), в режиме взаимности — **20%**
     (`reciprocityWinFeeBps = 2000`). Выигрыш — банк без собственной ставки победителя.
   - Пример, ставки по 10: победитель +8,771, проигравший −10,229, площадка +1,458
     (во взаимности: +7,771 / −10,229 / +2,458). Округление — вниз, в пользу игрока.
2. **Крупье — пользователь-девушка** (пол из KYC), не сотрудник площадки: выбирает декорации, включает
   камеру и играет на свои деньги. Игрок — место 0 (ЧЁТ), крупье — место 1 (НЕЧЁТ). KYC, договор,
   согласие на формат и модерация крупье — на стороне площадки (есть).
3. **Режим взаимности** открывается всем игрокам после 3 раундов с крупье, без проверки 18+: в нём нет
   интима, только аксессуары и верхняя одежда из фиксированного списка. При победе игрок получает
   деньги и предмет снимается.

## 2026-10-20. Ledger (этап 2)

1. **Баланс счёта — кэш в `wallet_account.balance`**, меняется только в одной транзакции с проводками.
   Инварианты держит БД: сумма проводок транзакции = 0 и одна валюта (отложенный триггер),
   `balance ≥ 0` для счетов без `allow_negative` (CHECK), `ledger_tx`/`ledger_entry` только дописываются.
2. **Минус разрешён только системным счетам-источникам**: `gateway_clearing` (USDT) и `fun_issuance` (FUN).
   Сумма всех балансов по валюте всегда 0.
3. **Идемпотентность** — уникальный `ledger_tx.idempotency_key`, производный от доменного события
   (`deposit:{intentId}`, `stake:{roundId}:{userId}`, `settle:{roundId}` …).
4. **`round_pot` — один системный счёт на валюту**, раунды различаются по `ref`. Если станет узким
   местом под нагрузкой — перейти на счёт банка на раунд.
5. **Chargeback** (этап 3): `main` пользователя не уходит в минус по CHECK, поэтому недостачу при
   chargeback нужно будет учитывать отдельным счётом долга, а не минусом на `main`.
6. **Фантики**: стартовый баланс `funStartingBalance` выдаётся один раз при первом обращении к кошельку.
   Правила пополнения фантиков — уточнить по ТЗ.

## 2026-10-20. Гостевая игра, регистрация, валюта, гео

1. **Гостевая игра на фантиках без регистрации.** Пользователь получает `user_id` (UUIDv7) и токены
   при первом входе с устройства (`kind = guest`). Игра идёт на фантиках — валюта `FUN`, отдельные
   очереди и счета; в USDT не конвертируется.
2. **Регистрация — только для реальных денег.** Нужна при первом пополнении: OTP по SMS или email.
   Гость становится `registered` с тем же `user_id`. Если контакт уже принадлежит другому
   пользователю, OTP — это вход в тот аккаунт (гостевой остаётся брошенным).
3. **Расчётная валюта ledger — USDT**, minor unit = 10⁻⁶ USDT (как у USDT в сетях). Закрывает открытый
   вопрос payments.md §7.
4. **Гео — по IP и по стране из KYC.** Для реальных денег и 18+ обе страны должны быть разрешены; если
   KYC-страна известна и не совпадает с IP-страной — реальные деньги блокируются (`geo_mismatch`,
   выключается конфигом).

Следствия:

- Вывод — только после KYC (payments.md §6); игра на USDT — после регистрации и KYC
  (`kycRequiredForRealPlay`, по умолчанию включено — сверить с ТЗ).
- Модуль 18+ требует KYC независимо от валюты, так что гость в 18+ не попадает.
